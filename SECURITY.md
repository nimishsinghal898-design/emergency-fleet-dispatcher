# Security Policy & Architecture

## 1. Overview
The Emergency Fleet Command System is engineered with defense-in-depth principles. Even as an algorithmic simulation platform, it adheres to modern enterprise web security standards to prevent injection, resource exhaustion, path traversal, and information disclosure.

---

## 2. Input Validation & Schema Enforcement

All client interactions with the FastAPI backend pass through Pydantic v2 data models that enforce strict boundary rules before any engine execution begins:

```python
class SimulationRequest(BaseModel):
    seed: int = Field(default=20260911, ge=0, description="Random seed for scenario generation")
    dispatcher_type: DispatcherType = Field(default=DispatcherType.COVERAGE, description="Dispatcher strategy")
    num_vehicles: int = Field(default=20, ge=1, le=100, description="Vehicle fleet size")
    num_incidents: int = Field(default=100, ge=1, le=500, description="Incident volume")
    experimental_mode: bool = Field(default=False, description="Enable scale testing")
```

- **Numeric Bounds**: Fleet size is capped at 100 and incidents at 500 to prevent denial-of-service (DoS) via intentional memory or CPU exhaustion.
- **Enumerated Dispatcher Types**: Only registered dispatchers (`"coverage"` and `"baseline"`) are accepted. Arbitrary class names or reflection paths are rejected.
- **Automatic Rejection**: Malformed payloads or out-of-bound arguments immediately trigger an `HTTP 422 Unprocessable Entity` response with structured validation diagnostics.

---

## 3. CORS (Cross-Origin Resource Sharing)

The FastAPI application implements a strict origin whitelist:
```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://localhost:5173",
        "http://127.0.0.1:5173",
        "http://localhost:8000",
        "http://127.0.0.1:8000"
    ],
    allow_credentials=True,
    allow_methods=["GET", "POST", "OPTIONS"],
    allow_headers=["*"],
)
```
- Wildcards (`"*"`) are disallowed in production mode.
- Requests originating from external unlisted domains are blocked by the browser.

## 4. API Security & Payload Protection

### 4.1 Request Size Limiting
An ASGI middleware inspects `Content-Length` headers before body parsing:
- Payloads exceeding **1,048,576 bytes (1 MB)** are rejected immediately with **`HTTP 413 Payload Too Large`**.
- Invalid or spoofed `Content-Length` headers trigger an immediate **`HTTP 400 Bad Request`**.

### 4.2 Hardened Response Security Headers
Every HTTP response generated by the application includes defense headers:
- `X-Content-Type-Options: nosniff`: Prevents MIME-type sniffing.
- `X-Frame-Options: DENY`: Mitigates clickjacking attacks.
- `X-XSS-Protection: 1; mode=block`: Activates browser XSS filtering.
- `Referrer-Policy: strict-origin-when-cross-origin`: Restricts referrer leakage.

## 5. Path Traversal Protection (CWE-22)

When serving pre-compiled frontend static assets from the FastAPI server, the application implements canonical path verification:

```python
raw_url = str(request.url)
if ".." in catchall or ".." in raw_url or "%2e" in raw_url.lower():
    raise HTTPException(status_code=403, detail="Access denied: path traversal attempt detected.")

safe_base = frontend_path
target_path = os.path.abspath(os.path.join(safe_base, catchall))
if not target_path.startswith(safe_base):
    raise HTTPException(status_code=403, detail="Access denied: invalid file path.")
```

- Any attempt to escape the designated `dist/` directory via `../`, `%2e%2e`, or symbolic links is caught and rejected with **`HTTP 403 Forbidden`**.

---

## 6. Secrets Management & Operational Isolation

- **Zero Hardcoded Secrets**: The architecture requires no external database connections, API keys, private certificates, or cloud secrets.
- **In-Memory Volatility**: Simulation runs, event timelines, and assignment states are stored strictly in volatile memory. No user data or sensitive files are written to unprotected temporary disk locations.
- **Docker Privilege Demotion**: The production container creates and switches to an unprivileged system user (`appuser`):
  ```dockerfile
  RUN useradd -m appuser && chown -R appuser /app
  USER appuser
  ```
  This eliminates container-breakout risks associated with running processes as root.

---

## 7. Prevention of Unsafe Operations

- **No Dynamic Code Execution**: The codebase contains zero instances of `eval()`, `exec()`, `os.system()`, or `subprocess.Popen()`.
- **Pure In-Memory Export**: All CSV and JSON export endpoints (`/export/json`, `/export/csv`, `/assignments`, `/coverage`) synthesize structured responses purely from in-memory objects using Python's standard `json` and `csv` libraries, eliminating file injection vulnerabilities.

---

## 8. Error Handling & Information Disclosure Prevention

The application deploys layered exception handlers:
1. **`StarletteHTTPException` Handler**: Preserves client-facing operational status codes (400, 403, 404, 413, 422) with sanitized error messages.
2. **Global Exception Handler**:
   ```python
   @app.exception_handler(Exception)
   async def global_exception_handler(request: Request, exc: Exception):
       logger.error("Unhandled exception: %s", exc, exc_info=exc)
       return JSONResponse(
           status_code=500,
           content={"detail": "Internal Server Error. Please check backend logs."}
       )
   ```
   - Python stack traces, internal variable values, and host filesystem structures are logged to secure server-side stderr and **never** returned across the wire to the client.
